# 도감 탐색·비교 개선 설계

사용자가 제공한 상세 요청서와 기존의 자율 구현 지시에 따라 진행한다. 순수 정적 HTML/CSS/JS, 공개 URL, 네이비·민트 디자인과 검수된 이미지 정책을 유지한다. 작업 브랜치와 PR까지만 만들며 main 병합·push·배포는 하지 않는다.

## 확인한 원인과 선택

- 홈의 33개·오늘의·DOCUMENTARY PHOTO는 고정 문구다. 실제 카탈로그 337개와 분야 개수를 공통 데이터에서 생성한다.
- 검색은 소문자 부분문자열, 국가는 전체 문자열 완전일치다. 검색 표기를 정규화하고 검증된 이름·모델·기존 별칭을 색인한다. 관련 국가는 개발국을 뜻하지 않으며 기존 명시 관계만 분리한다.
- 비교는 서로 다른 facts 키의 합집합이다. 형식·단위·조건·직접 출처가 연결된 별도 제원 프로필을 사용한다. 미수집/비공개/해당 없음은 서로 다른 상태다. 모호한 기존 사실은 검증된 수치처럼 합치지 않는다.
- 모바일 도감 필터가 첫 결과를 과도하게 밀고 비교 출처가 좁게 줄바꿈된다. 고급 필터는 접고, 비교는 의미 있는 표를 영역 내부에서만 가로 스크롤한다.

별도 프레임워크·서버는 이 규모에 불필요하다. 숫자만 교체하면 재발하므로 Node 표준 라이브러리로 작은 정적 생성·검증 절차를 추가한다. 런타임과 생성기가 같은 순수 함수를 사용한다.

## 데이터와 화면

- `data/catalog.json`: 공개 항목·기본 정보·관련 국가·기존 별칭·개별 자료 검토일·검증된 이미지 크레딧의 원본. 기존 337개와 265개 이미지 보존.
- `data/editorial.json`: 공식 직접 출처, 형식별 제원 프로필, 이번에 검토한 M1/F-35 본문. 동일 프로필을 본문과 비교에서 재사용한다.
- `assets/catalog-core.js`: 검색·국가·정렬·24개 페이지 분할·URL 상태·비교 항목 의미 구분. 브라우저와 Node에서 공유한다.
- `scripts/build.mjs`: 정적 첫 목록, 전체 이름 링크, 초기 개수, 카탈로그 JS, 대표 본문·비교 첫 화면 및 공통 메타데이터 생성. `--check`로 재생성 누락을 검출한다.
- `assets/site.js`: 접근 가능한 필터·페이지·비교 선택·URL/뒤로가기 복원. 인기순이나 성능 점수는 만들지 않는다.

기본 순서는 명시한 대표 기종과 이미지 준비 항목 우선, 이름순을 제공한다. 이미지 없는 항목은 큰 빈 그림 대신 작은 상태 배지를 사용하며 계속 검색·열람할 수 있다. 전체 337개 정적 상세 링크를 유지한다.

비교는 분야와 이름으로 대상을 좁히고 형식을 명시한다. 양쪽 출처 확인 항목을 먼저, 나머지·미수집 자료를 다음에 표시한다. `전투중량`과 단순 `Weight`, 전투행동반경과 항속거리, 최고속도 조건 등을 이름만 같게 묶지 않는다.

## 검증·결과물

검색 표기 세 묶음, 국가 혼동/복합 국가, 전체 수/분야 수, 비교 항목 의미, 잘못된 URL과 악성 문자열을 Node 테스트로 고정한다. 정적 링크·이미지·canonical·소유확인·구조화 데이터와 재생성 일치를 검사한다. 실제 브라우저에서 검색·필터·페이지·비교·공유·새로고침·뒤로가기, 키보드, JS 없는 정적 링크를 검증한다.

360/390/768/1440px의 홈·도감·비교·M1·F-35 전후 화면을 보관한다. 성능은 동일 로컬 환경에서 측정한 DOM·전송량·요청 수만 보고하며 공개 서버 성능 향상으로 일반화하지 않는다. 기사별 기존 검토일은 보존하고 실제 새로 확인한 두 글만 검토일을 갱신한다.
